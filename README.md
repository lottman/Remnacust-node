# Remnacust Node

Агент Xray для Remnacust: получает конфигурацию от панели, управляет процессом ядра и передаёт статистику. Расширения хостов, квот, скорости и устройств требуют совместимого Remnacust Core.

## Текущий стабильный комплект

| Компонент | Версия |
| --- | --- |
| Node | [1.1.20](https://github.com/lottman/Remnacust-node/releases/tag/v1.1.20), основа Remnawave Node 3.4.3 |
| Встроенное ядро | [Core 1.1.12](https://github.com/lottman/Remnacust-core/releases/tag/v1.1.12), стабильный Xray v26.10.31 |
| Панель и страница подписки | [1.1.7.85](https://github.com/lottman/Remnacust-panel/releases/tag/v1.1.7.85) |
| Готовый Docker-комплект | [1.2.121](https://github.com/lottman/Remnacust-installer/releases/tag/v1.2.121), Linux amd64/arm64 |

Обновление одной панели не заменяет ядро удалённой ноды. В новом ядре MPTCP выключен по умолчанию; исходящий XDRIVE сохраняет сегментный формат для совместимости со старыми узлами. Обновление приложения не заменяет обновление ядра Linux на сервере.

## Установка

Установщик поддерживает Ubuntu 22.04/24.04/26.04 LTS, Linux amd64/arm64. Для ноды нужен запас от 1 CPU и 1 GiB RAM; реальные требования зависят от соединений и правил. Node.js и Go на VPS не нужны.

Создайте ноду в панели, скопируйте ключ подключения, затем выполните:

```bash
curl -fsSL --proto '=https' --proto-redir '=https' https://github.com/lottman/Remnacust-installer/releases/latest/download/installer.sh -o installer.sh
sudo bash installer.sh install-node --version 1.2.121
```

Скрипт запрашивает API-порт, ключ, сетевые ограничения и при необходимости TLS/XHTTP. По умолчанию API использует 2222; такой же порт укажите в карточке ноды. Затем назначьте профиль, включите inbound, разрешите его скваду и создайте хост с клиентским адресом/портом.

`NET_ADMIN` — право контейнера, а не отдельный пакет Xray. Оно нужно части сетевых операций и принудительному закрытию соединений. Установщик предлагает его при установке/обновлении; существующее включённое право сохраняется. Используйте `--net-admin` или `--no-net-admin` для явного выбора.

Опция `--panel-ip` ограничивает **все входящие порты и ICMP адресом панели, кроме SSH**. Это не только защита API: прямые клиенты и CDN с другими исходными IP потеряют доступ к inbound. Выбирайте режим только для соответствующей схемы подключения. HTTP-01 временно открывает TCP 80 на период выпуска/продления сертификата.

## Где находятся файлы

```text
/opt/remnacust/node/.env
/opt/remnacust/node/docker-compose.yml
/opt/remnacust/FILES.txt
/opt/remnacust/backups/
/opt/remnacust/logs/
```

Точные пути установленного проекта смотрите в `FILES.txt`. Старые собственные каталоги можно привести к постоянному пути через `sudo remnacust normalize-layout --component node`. При обновлении сохраняйте не только `.env`, но и постоянное состояние ноды и ядра, указанное в Compose mounts. Не удаляйте журналы квот/политик для обхода проверки совместимости.

После изменения `.env` пересоздайте контейнер:

```bash
cd /opt/remnacust/node
docker compose config --quiet
docker compose up -d --no-build --pull never
```

## Канал управления

Внешний HTTPS API проверяет сертификат и JWT ноды. Доступ к API-порту дополнительно ограничивается сетевым правилом; это отдельный вопрос от доступа клиентов к портам Xray. Проверка TLS не отключается ради обхода ошибки подключения.

Внутренние gRPC и HTTP-каналы Xray используют приватные файловые Unix sockets с правами `0600` в закрытом каталоге. Клиентам они не выдаются. Агент проверяет версию и результат применения конфигурации.

Работающие Xray-процессы и совместимые политики продолжают обслуживать соединения независимо от HTTP-доступности панели. Конкретные гарантии ограничены режимом квоты и сохранённой политикой; старые ноды могут требовать обновления. Не выдавайте недоступность панели за подтверждённую автономность любого прежнего ядра.

## Скорость, квоты и устройства

Предел пользователя суммирует его устройства на заданном хосте; предел устройства суммирует соединения персонального ключа и оба направления. Активные ключи делят пользовательский бюджет, дополнительные потоки не увеличивают долю. При общем пределе сначала делятся бюджеты пользователей. Единицы панели — Mbps; объём — GiB.

Отзыв доступа использует авторизованную идентичность ключа: другие устройства за одним NAT не должны отключаться вместе с ним. Работа расширений зависит от возможностей ядра; обычный upstream Xray не заменяет их автоматически. [Области лимитов](https://github.com/lottman/Remnacust-panel/blob/main/docs/HOST-LIMITS.md).

## Обновление и обслуживание

```bash
sudo remnacust upgrade-node
sudo remnacust manage-node
sudo remnacust status --component node
sudo remnacust logs --component node
sudo remnacust restart --component node
```

`upgrade-node` обновляет агент и встроенный Xray, сохраняя ключ, порты, mounts и проект. Замена процесса может прервать соединения. Совместимое runtime-применение профиля не требует обязательного рестарта; несовместимая смена listener должна быть явной операцией обслуживания.

Перенос: `sudo bash installer.sh migrate-remnawave-node --container remnanode`. Смена домена и сертификаты описаны в [руководстве установщика](https://github.com/lottman/Remnacust-installer/blob/main/installer/README.md).

## Сборка из исходников

Из корня checkout:

```bash
docker build -f node/docker/Dockerfile -t remnacust-node:local node
```

Dockerfile использует проверяемый архив Core в `node/docker`; архив и файлы внутри проверяются по SHA-256. Изменение README не требует перепаковки опубликованного архива или замены его версии. Если меняете само ядро, подготовьте соседний Remnacust-core и выполните `python3 node/docker/package-remnacust-core.py`, затем проверьте и пересоберите согласованный комплект.

Для разработки: [node/README.md](node/README.md). Для ручного запуска заполните `node/.env` по образцу; source-Compose находится в `node/docker-compose-prod.yml` и использует host networking.

## Если подключение не работает

Проверьте адрес, API-порт, ключ, TLS и firewall. Затем — состояние Xray, активный inbound, клиентский порт, хост, сквад и актуальность подписки. После обновления проверьте обе версии: агента и ядра. Статус API online сам по себе не доказывает доступность клиентского пути через CDN.

## Xera HTTP

`network: "xera-http"` и `xeraHttpSettings` — расширение XHTTP, требующее совместимых ядер клиента и ноды. Обычный XHTTP остаётся отдельным транспортом. [Описание](https://github.com/lottman/Remnacust-panel/blob/main/panel/frontend/public/documentation/guide-ru.md#транспорт-xera-http).
