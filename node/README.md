# Remnacust Node

Установка через консоль на Ubuntu 22.04 LTS, 24.04 LTS или 26.04 LTS (amd64/arm64):

```bash
curl -fsSL --proto '=https' --proto-redir '=https' https://github.com/lottman/Remnacust-installer/releases/latest/download/installer.sh -o installer.sh && sudo bash installer.sh install-node
```

Сначала создайте ноду в панели. Скрипт спросит её ключ и версию выпуска установщика; Enter выбирает `latest`. [Скачать installer.sh](https://github.com/lottman/Remnacust-installer/releases/latest/download/installer.sh).

Инструкции установки, сборки, совместимость и лицензии: [README репозитория](../README.md).

## 2026-10-17: подготовка доставки независимых профилей, неопубликованный код

Добавлены внутренние `makeProfileInput`, `LiveCoreService.applyProfiles` и `prepareProfileRestart`. Мост проверяет хеши графов и плана, UUID привязок, владельца и версию доставки; сохраняет копию конфигурации в приватный синхронизированный файл и вызывает новые команды Core `api profile-apply` / `api cache-profiles`. Конфигурации и ключи не попадают в аргументы команд. Ответ принимается только для ожидаемой доставки и количества графов. Подготовка перезапуска сохраняет обязательную политику квот.

Основной обработчик `XrayService.startXray` и запрос подготовки в панели пока используют прежний объединённый конфиг. Новые методы ещё не подключены к этому пути, возможность независимых графов не объявляется готовой. Изменение состава графов, освобождение портов после завершения старых соединений и полный сквозной аудит остаются необходимыми перед выпуском.

В Core исправлен выбор существующих CLI-команд, включая `require-user-quota` и `usage-receipt`: строки справки больше не мешают диспетчеру определять имя команды. Проверки нового CLI запускают отдельные процессы с настоящим диспетчером и реальным VLESS-трафиком. Это не заменяет проверку установленной панели и ноды. Разделы от 15 октября ниже описывают состояние предыдущих этапов.

## Квитанции расхода: неопубликованный код

`POST /node/xray/usage-receipts` защищён обычным RS256 JWT ноды. Запрос содержит `action: sample|ack`, `stream` из `quotaInstanceId`, десятичную строку `sequence` и `coreProcessId`; ACK также содержит digest снимка. Нода вызывает только поддерживающее протокол работающее ядро через приватный сокет. Ответы проверяются и ограничиваются; при неопределённом результате нельзя заменять запрос legacy reset.

Состояние находится в `/var/lib/remnanode/usage/receipt.json`. Сохраняйте весь `/var/lib/remnanode` при обновлении, переносе и откате. Ядро без поддержки квитанций при наличии этого состояния не активируется. SHA-256 — проверка целостности, файл не зашифрован; права и резервные копии должны оставаться приватными.

Автоматический координатор и автономный общий лимит пользователя ещё не завершены. Новый сборщик используется только для уже зарегистрированного режима; обычная установка автоматически на него не переводится.

## Неопубликованный режим независимых портов

Панель передаёт полный план ноды с `internals.portPlan: {revision, enabled}`. Версия — положительная десятичная строка int64. Включённый режим требует live-применения на поддерживающем ядре; отдельный `forceRestart` означает явно запрошенное обслуживание. Старый запрос без версии не заменяет уже зарегистрированный план.

Приватный файл `/var/lib/remnanode/core/port-plan-state.json` сохраняет принятую версию, требование native ports и последнюю подтверждённую версию. Сохраняйте его вместе со всем `/var/lib/remnanode` при переносе и восстановлении. При незавершённом отключении режима требование совместимого ядра остаётся включённым. Выбор ядра и текущий boot-guard проверяют это требование до запуска публичных слушателей. Произвольный старый образ ноды или неполная копия состояния требуют отдельной проверки совместимости; удаление файла не является способом отката.

Проверки текущего этапа: 80/80 Node-тестов в Linux без сети. Полный интерфейс портов, независимые глобальные приложения профилей, сквозной аудит и выпуск остаются незавершёнными; статус NOT READY.
