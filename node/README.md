# Remnacust Node — исходники агента

**Агент 1.1.20**, основа Remnawave Node 3.4.3. Docker-образ включает Remnacust Core 1.1.12 на стабильном Xray v26.10.31. Согласованный установщик — 1.2.122; панель/страница — 1.1.7.86.

## Установка и файлы

Для сервера используйте [инструкцию репозитория](../README.md#установка). Файлы скриптовой установки: `/opt/remnacust/node/.env` и `/opt/remnacust/node/docker-compose.yml`. Активные пути перечислены в `/opt/remnacust/FILES.txt`.

При source-запуске скопируйте [.env.sample](.env.sample) в `.env`, заполните `NODE_PORT` и `SECRET_KEY` из панели, задайте права `600`. API-порт должен совпадать с карточкой ноды. [docker-compose-prod.yml](docker-compose-prod.yml) использует host networking; сетевые правила API и клиентских inbound задавайте осознанно.

## Разработка

Нужен Node.js 24. Из этого каталога:

```bash
npm ci
npm run typecheck
node --test tests/*.test.cjs
npm run build
```

Проверки Unix sockets, владельцев файлов и сетевого поведения выполняются на Linux. На Windows результат таких проверок не равнозначен Linux. [Source checks](../.github/workflows/check.yml) фиксирует команды CI.

В backend панели есть проверки взаимодействия с реальным транспортом ноды; `REMNACUST_NODE_SOURCE` указывает на этот каталог. Используйте временные сертификаты, loopback-серверы и тестовую БД, а не действующую клиентскую инфраструктуру.

## Ядро и совместимость

Архив в [docker](docker) проверяется по SHA-256 до сборки. Версия агента не равна версии Core. При выборе ядра сохраняются проверки действующих политик и приватного состояния; установка старого несовместимого бинарника не является безопасным откатом.

Runtime-применение совместимых изменений, отзыв устройств, host-policy и счётчики описаны в [README](../README.md) и [таблице совместимости](../docs/NODE-COMPATIBILITY.md). Независимые графы и протоколы recovery имеют отдельные границы готовности; не включайте экспериментальный режим только на основании имени метода в исходниках.
