# Remnacust Node — исходники агента

Стабильный агент **1.1.22** основан на Remnawave Node 3.4.3. Опубликованный комплект: Installer **1.2.136**, панель/страница **1.1.7.97**, Core **1.1.13 / Xray v26.10.31**. Текущий checkout может содержать ещё не выпущенные изменения.

## Для оператора

Используйте [инструкцию установки и обслуживания](../README.md). Стабильный установщик поддерживает Ubuntu 22.04/24.04/26.04 LTS, Linux amd64/arm64; Debian 12/13 добавлен локально, но ещё не опубликован. Начальный ориентир — 1 CPU и 1 GiB RAM без гарантии ёмкости. На VPS с готовым образом Node.js и Go на хосте не нужны.

Постоянные файлы: `/opt/remnacust/node/.env` и `/opt/remnacust/node/docker-compose.yml`; фактические пути — в `/opt/remnacust/FILES.txt`. Сохраняйте `SECRET_KEY`, конфигурацию, сертификаты и все три каталога состояния из корневого README. Старый контейнер без mounts сначала остановите и скопируйте его приватное состояние с владельцами и правами; не скрывайте его пустыми mounts при recreate.

## Локальная конфигурация

Для source-запуска скопируйте [.env.sample](.env.sample) в `.env` и заполните ключ из панели:

```dotenv
NODE_PORT=2222
SECRET_KEY=SECRET_KEY_FROM_PANEL
```

Ограничьте права `.env` до `600` и не добавляйте секреты в Git. API-порт должен совпадать с карточкой ноды. [docker-compose-prod.yml](docker-compose-prod.yml) — source-конфигурация с host networking и локальной сборкой, а не указатель актуального стабильного образа. Для готового комплекта используйте установщик из корневого README.

Внешний API требует mTLS и JWT. Разделяйте правила доступа к API и клиентским inbound. Внутренние Unix sockets и состояние должны оставаться приватными.

## Разработка и проверки

Нужен **Node.js 24**. Из этого каталога:

```bash
npm ci
npm run typecheck
node --test tests/*.test.cjs
npm run build
```

Проверки Unix sockets, владельцев, прав и сетевого поведения выполняйте на Linux; Windows не заменяет эту среду. Команды CI: [Source checks](../.github/workflows/check.yml).

Docker-образ собирается из корня репозитория:

```bash
docker build -f node/docker/Dockerfile -t remnacust-node:local node
```

Архив Core в [docker](docker) проверяется по SHA-256. Изменение Core требует полного соседнего checkout Remnacust-core, Go **1.27.3** и согласованной перепаковки через `python3 node/docker/package-remnacust-core.py` из корня репозитория. Для изменения README это не требуется. [Сборка](../docs/BUILDING.md).

## Ядро, автономность и совместимость

Агент и Core обновляются отдельно; образ включает встроенное ядро, но выбранный managed Core может оставаться закреплённым. Проверяйте активную версию, а не только версию образа. Замена процесса может прервать соединения.

Работа без панели ограничена сроками доступа, оставшимся кредитом USER/HOST/TAG и границами квотного периода; календарный сброс не пополняет кредит offline. Restart требует сохранённых конфигурации, credentials и журналов. Суточная автономность требует достаточного запаса и совместимого комплекта. Локальные watchdog/recovery-исправления ещё не входят в стабильный Node 1.1.22; для полного восстановления нужны новые Node и Core.

Стандартные профили сохраняют совместимость с legacy-клиентами в пределах их возможностей. Расширения Remnacust и Xera требуют совместимых компонентов; не отключайте проверки политик ради отката. [Совместимость](../docs/NODE-COMPATIBILITY.md) · [Условия автономности](https://github.com/lottman/Remnacust-panel/blob/main/docs/NODE-AUTONOMY.md).
