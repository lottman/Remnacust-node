# Remnacust Node 1.1.37

Управляющие обращения к Core используют общий дедлайн 15 секунд и отмену RPC. Отмена распространяется на выполняемые обращения; после истечения срока новые шаги операции не должны продолжаться. Core 1.1.22 учитывает отмену также в прежних gRPC-операциях пользователей и статистики после ожидания. Тайм-аут или отмена не откатывают изменения, которые Core уже успел применить. Перед повтором изменения пользователя или сброса статистики проверяйте фактический результат.

Изменения конфигурации, пользователей и чтение статистики со сбросом счётчиков защищены от одновременного выполнения. Занятый или ещё не готовый Core возвращает временную неготовность, а не успешный пустой результат; повторяйте операцию после синхронизации. Защита освобождается после завершения или ошибки, сохраняя проверку готовности Core и журналы квот.

Core 1.1.22 добавляет необязательные профили Xera HTTP: balanced, low-latency и unstable-network. Они регулируют параллелизм по измеренным HTTP-ответам, передаче данных и ожиданию запросов. В adaptive обязательны mode, minStreams и maxStreams. Целые границы — от 1 до 32, минимум не больше максимума; форма панели предлагает 4/32, начальный предел 8 ограничивается диапазоном. Минимум не создаёт запросов в простое.

Считаются одновременно активные HTTP-запросы отдельно для каждого направления, назначения и версии настроек транспорта, а не TCP-соединения, пользователи или CPU. Подстройка не прерывает и не повторяет начатые запросы. Без adaptive сохраняются прежнее поведение, ручной JSON и extra; режимы передачи auto/stream-auto, ALPN, padding и квоты не меняются. Для применения нужен Core 1.1.22 или новее у клиента с поддержкой Xera HTTP. Связь Core 1.1.22↔1.1.21 проверена в Linux: 82/82 сценария IPv4/IPv6 с TLS HTTP/1.1, HTTP/2, HTTP/3 и REALITY, четырьмя прежними режимами и тремя профилями адаптации. Профили не обучают ИИ и не гарантируют невидимость для DPI или преимущество в конкретной стране. [Руководство Xera](https://github.com/lottman/Remnacust-core/blob/main/docs/XERA-HTTP.md).

Core 1.1.22 также ограничивает ожидающие сегменты WAL в XDRIVE, завершает застрявшую передачу по TTL сессии и очищает данные закрытых сеансов с повтором после ошибок хранилища. Исправления WAL и отмены gRPC сохраняют прежние форматы обмена и конфигурации, новых настроек не требуют.

Кандидат Node 1.1.37 `49172af` прошёл [SourceCI](https://github.com/lottman/Remnacust-node/actions/runs/43655383959), включая первый запуск после переноса с реальным Core 1.1.22.

Комплект: Node 1.1.37, Core 1.1.22 на официальном Xray v26.11.9, Panel/Page 1.1.7.126, Installer 1.2.174. Обновление панели не обновляет удалённую ноду или клиентское приложение. Отдельно закреплённое managed-ядро может остаться выбранным после обновления образа: проверьте активные версию и режим. Сохранённые права, квоты и приватное состояние не удаляются ради обновления.

## English

Management calls to Core use a shared 15-second deadline and RPC cancellation. Cancellation reaches active calls; later operation steps must not continue after expiry. Core 1.1.22 also honors cancellation in legacy gRPC user and statistics operations after waiting. A timeout or cancellation does not roll back changes Core has already applied. Check the actual result before repeating a user mutation or statistics reset.

Configuration changes, user mutations and statistics reads that reset counters are protected from overlapping execution. A busy or unready Core returns temporary unavailability rather than a successful empty result; retry after synchronization. Protection is released after completion or failure, preserving Core readiness checks and quota journals.

Core 1.1.22 adds optional Xera HTTP profiles: balanced, low-latency and unstable-network. They adjust concurrency using measured HTTP responses, data transfer and request waiting. All three adaptive fields are required: mode, minStreams and maxStreams. Integer bounds range from 1 to 32, with the minimum no greater than the maximum; the panel form offers 4/32 and clamps the initial limit of 8 into that range. The minimum creates no idle requests.

Limits count simultaneously active HTTP requests separately for each direction, destination and generation of transport settings, rather than TCP connections, users or CPU. Adjustment does not abort or replay existing requests. Without adaptive, previous behavior, manual JSON and extra remain available; auto/stream-auto transfer modes, ALPN, padding and quotas are unchanged. Adaptation requires Core 1.1.22 or later in a client supporting Xera HTTP. Native Linux interoperability between Core 1.1.22 and 1.1.21 passed 82/82 IPv4/IPv6 scenarios covering TLS HTTP/1.1, HTTP/2, HTTP/3 and REALITY, four existing modes and three adaptation profiles. Profiles do not train AI or guarantee DPI invisibility or an advantage in any particular country. [Xera guide](https://github.com/lottman/Remnacust-core/blob/main/docs/XERA-HTTP.md).

Core 1.1.22 also bounds pending XDRIVE WAL segments, ends stalled transfers at the session TTL and cleans closed-session data with retries after storage errors. The WAL and gRPC cancellation fixes retain existing wire and configuration formats and require no new settings.
