# 1.1.21

Обычное обновление профиля сначала применяет изменения через native runtime API. Если ядро точно отклоняет смену порта или транспорта существующего inbound, агент проверяет конфигурацию, сохраняет рабочий приватный checkpoint и автоматически перезапускает только Xray. Если новый процесс не становится готовым, агент останавливает неудачный процесс, восстанавливает прежний checkpoint и проверяет запуск старой конфигурации. Краткий разрыв соединений возможен.

Таймаут, неизвестный результат RPC, некорректная конфигурация и повреждённый checkpoint не разрешают этот переход. Строгий `requireLiveApply` и управляемые планы сохраняют прежнее требование горячего применения. Пользовательский индекс и подтверждение доставки обновляются только после успешного применения. Рабочая конфигурация не попадает в аргументы команд или сообщения об ошибках.

Проверены приватные права, владелец, тип и размер checkpoint, отсутствие символических ссылок, целостность SHA-256 и оба поддерживаемых заголовка, включая обязательную политику пользовательских квот. Откат записывается через закрытый временный файл и атомарное переименование. Перезапуск не меняет правила firewall, NET_ADMIN, доступ к API и выбор ядра.

На опубликованном Core 1.1.12 проверены настоящие VLESS-соединения, смена порта, смена TCP на WebSocket на том же порту, неизменный PID при повторном применении и восстановление после занятого порта. Полная проверка Node на Linux: 197 тестов без ошибок и пропусков. Встроенное ядро остаётся 1.1.12 на стабильном Xray v26.10.31.

Готовый согласованный комплект: установщик 1.2.125, панель и страница подписки 1.1.7.87. Обновление одной панели не заменяет образ удалённой ноды.
